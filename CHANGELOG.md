Security and durability hardening. No action is required for existing data:

### Supply chain
* Vendored pako 2.1.0, CryptoJS 4.2.0, Font Awesome 6.5.1 and JetBrains Mono.
  The app no longer loads anything from a CDN, Google Fonts included.
* Added a strict Content-Security-Policy (`default-src 'none'`, `connect-src 'none'`,
  `worker-src 'self'`) and a test that fails if a third-party subresource ever
  appears again.
* Added `assets/vendor/CHECKSUMS.txt` and a CI check over its SHA-256 digests.
* Workers are now real files under `assets/js/workers/` instead of `blob:` URLs.

### Cryptography
* New `KRX5` text envelope: the header (version, profile, cipher, KDF,
  iteration count, salt, IV, encoding) is authenticated as GCM additional data,
  so parameters can no longer be tampered with or downgraded.
* New `KRXFILE2` file container: magic bytes, version, cipher/KDF ids and
  iteration count in an authenticated header, plus the original filename stored
  inside the ciphertext.
* Every field read from an untrusted blob is validated before a key is derived
  (iteration bounds 100kâ€“4M, salt/IV sizes, ciphertext cap).
* PBKDF2 work factors raised to 600k (standard), 1M (advanced) and 2M (maximum);
  file sealing and new vaults use 600k. Older blobs keep their own parameters.
* Decryption now caps the inflated output (256 MiB) to stop decompression bombs.
* Hash options previously labelled `SHA3-256/512` were in fact Keccak; they are
  now labelled `Keccak-256/512` and pinned by a NIST/Keccak test vector.
* Added `verifySeal()`: encryption re-decrypts its own output before the result
  is shown.

### Data safety
* Text and file encryption now require the passphrase to be entered twice, and
  sealing is verified end to end before the download is offered.
* The vault gets encrypted export/import backups, cross-tab protection via the
  Web Locks API and a `storage` event listener that locks rather than
  overwriting another tab's work.
* Storage failures (quota exceeded, private mode) now surface as errors instead
  of silently dropping a save.
* Auto-lock, manual lock, wipe and external changes all run through one path
  that clears the editor, the search box and every passphrase field.
* The vault write path re-reads the store before saving, and refuses to write
  when the blob has disappeared.

### Generators
* Passphrase generation now uses the EFF large wordlist (7,776 words,
  12.9 bits/word) instead of a 108-word list, and displays live entropy.
* Password generation guarantees one character from each enabled class and
  shuffles with the CSPRNG.
* The strength meter estimates entropy and penalises common passwords and
  keyboard runs (`qwertyuiop1!` is no longer "strong").

### Performance and robustness
* Hash recovery generates mutations lazily: a 2 MB wordlist slice used to
  allocate ~2 GB of strings, which is now flat.
* Recovery is cancellable at any time (worker termination) and reports a live
  candidate rate.
* Removed the compression fallback bug where a transferred buffer left the
  main-thread path compressing an empty input.
* File hashing supports every offered algorithm, not just four.
* Added a boot check for a secure context and for missing libraries.

### Project
* Added MIT license, SECURITY.md with a threat model, CONTRIBUTING.md,
  CHANGELOG.md, `package.json`, CI workflow and issue/PR templates.
* Added `node:test` suites (30 tests) covering formats, tamper detection,
  vault lifecycle, static integrity, plus fixtures generated by an independent
  implementation.
* Documented the wire formats in `docs/FORMAT.md`.
* Added a favicon, theme colour, social meta tags and ARIA roles for the tabs.
